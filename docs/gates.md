## Gate → artifact mapping

Each gate checks artifacts produced BEFORE that gate fires. Dispatch keys live in `ui_clone/gate.py` `VALID_GATES`:

- `reference` (after Phase 1 / `/ui-capture`): `static/ref/` ≥5 PNGs, `transitions/ref/` ≥1 file, `regions.json`
- `extraction` (after Step 3): `structure.json`, `head.json`, `styles.json`, `fonts.json`, `visible-images.json`, `inline-svgs.json`, `body-state.json`, `design-bundles.json`, `css/variables.txt`, `em-conversion.json` (if `scalingSystem ≠ px-fixed`)
- `bundle` (after 5c-a): `bundles/` (≥1 JS chunk; warns <3), `interactions-detected.json`, `scroll-engine.json`
- `paid-features` (after 5c-c): `paid-features.json` — every paid font CDN hit must have `decision` ∈ {`use`, `substitute`, `skip`}. Empty findings pass. GSAP plugins are not checked (GSAP is now 100% free). See `skills/visual-debug/scripts/paid-features-detect.sh`.
- `spec` (after 5d): `bundle-map.json`, `external-sdks.json`, `transition-spec.json` (validates each transition has id/trigger/source_chunk/bundle_branch/target/animation/reference_frames, and grounds `source_chunk` in captured `bundles/`, `css/`, or `html/` files unless it uses the `"inline init"` sentinel), `verification-plan.json` (produced by `skills/visual-debug/scripts/verification-plan.sh` — declares the site-specific required-check list including the universal hydration-check, proxy-mirror-check, and conditional Lottie/runtime rows; without it, `gate_post_implement` would silently skip those checks), `verify/` ≥5 frames. Also cross-validates against `paid-features.json`: any paid font marked `decision="substitute"` must have an entry in `asset-substitution.json` `fonts[]` — otherwise font-parity FAILs after generation.
- `pre-generate` (before Step 7): `extracted.json`, `transition-coverage.json`, `section-map.json`, hover timing resolved, `dom-state-diff.json` (if hasPreloader), `webflow-*` (if Webflow), audit artifacts (element-roles, element-groups, layout-decisions, component-map)
- `state-coverage` (between `pre-generate` and `post-implement`): multi-snapshot capture artifacts vs impl source. Reads `state-structure-spec.json` as the compact rollup plus `states/splash/trajectory.json`, `states/scroll/summary.json`, `states/hover/manifest.json`, and optional `states/click/manifest.json`, then verifies impl/src/** has matching hooks (class strings from splash transitions, scroll-state primitives like IntersectionObserver/ScrollTrigger/useScroll, hover handlers like `:hover`/`hover:`/`onMouseEnter`/`whileHover`, click state handlers when captured). Skips silently when `states/` directory is absent (legacy ref dirs predate the multi-snapshot capture pipeline). Partial captures check only the present phases. Produced by `scripts/extract/capture-states.sh` (Phase A splash), `scripts/extract/capture-scroll.sh` (Phase B scroll), `scripts/extract/capture-hover.sh` (Phase C hover), `scripts/extract/capture-click.sh` (click state), and `scripts/extract/state-structure-spec.py` (compact rollup).
- `post-implement` (after each transition impl): `extracted.json`, `transition-spec.json`, `static/ref` ≥5, plus every block-severity `verification-plan.json` artifact. Standard+ plans include `impl-url-guard.json` (local impl URL port must be served from the canonical `.impl-root`), `runtime-env.json`, and `live-parity.json`, a paired ref/impl `agent-browser` scroll census that fails visible pseudo duplication, broken assets, image inventory drift, missing fonts, and mask-hidden geometry/count drift. Quick+ plans include `capacity-report.json` so browser-heavy verification lanes use measured local capacity instead of guessing, and `alignment-parity.json` (`skills/visual-debug/scripts/alignment-parity-check.sh` — pure file IO over `sections/viewports/*/sections/matches.json`; compares section-box center offset, contentBox left/right-gap asymmetry, and per-container contentGroups asymmetry ref-relative per fan-out viewport (plus a per-child offset-distribution prong — `childCenters` — that catches a systematic OR symmetric-dispersion per-child shift hidden behind a SYMMETRIC union: it compares the sorted per-child offset SET ref-vs-impl by worst element-wise divergence, so 3+ children fanned so their median cancels to centre still fail, batch-8 ITEM 7); an unpaired IMPL-leftover content group is no longer assumed benign — one that is off-center in its own container (a decoy carrying the ref's class token, a duplicate same-name group, or the real cards under a renamed class consumed the ref pairing) fails (`group-leftover`) instead of being silently dropped, and the enumerator's paint filter (`paintsNothing` in `enumerate-sections.js`) excludes zero-paint spacer leaves (4px transparent-bg) so a zero-footprint decoy cannot dilute a union; lone masked content elements (a single masked heading a parent transform de-centers) are emitted as section-anchored `masked:` groups so their placement is measured ref-relative; frozen refs lacking contentBox fields report `warn` + recapture remediation, never a silent pass), and `junk-token.json` (`skills/visual-debug/scripts/junk-token-check.sh` — serialization junk `undefined`/`null`/`NaN`/`[object Object]` as standalone tokens in `className`/`id`/`src`/`href`/`alt`/`style`, scanned in impl source and in the runtime DOM across a scroll + settle sweep (re-scanning at each scroll step and after a longer settle so junk applied later via setTimeout or on scroll/timer — the loop-9 nav-dot class — is caught, not just what renders in the first ~2s); token membership strips default-ignorable Cf code points (ZWJ/ZWSP/ZWNJ/WJ/BOM) then NFKC + confusable-folds, so both a Cyrillic/Greek homoglyph ('undefinеd') and a zero-width-char insertion are caught; the scanned surface is widened beyond className/id/src/href/alt/style to data-*/aria-* and SVG presentation attributes (fill/stroke/...) by whole-value match (prose containing the word 'undefined' is not over-flagged), .astro joins the markup family, and .json files are value-walked — while interaction-gated junk (className mutated only on click/hover/route-change) and computed CSS-var/::before content remain a best-effort browser-only sweep, documented as NOT part of the static unit guarantee; and a runtimeScanned=true pass must bind to a resolvable impl_root — a forged artifact run against a standalone ref dir where no impl tree resolves is rejected by the post-implement consumer). All sites also get `alignment-sweep.json` (`skills/visual-debug/scripts/alignment-sweep-check.sh` — impl-only DOM-rect sweep at intermediate widths asserting ref-classified centered/fixed-gutter invariants; the width set now includes the IMPL's OWN @media boundaries ±1px (scanned from impl CSS into `impl-detected-breakpoints.json`, not just the ref's), and a single-viewport plan is no longer sweep-exempt (it widens to the desktop span around the impl breakpoints); blocks on two adjacent sweep-width violations or one enforced-width violation). Hover coverage is per-entry: a hover-state-compare run with 0 measured target-runs (all known-skips) can no longer pass — it invokes `skills/visual-debug/scripts/hover-fallback-probe.sh` (+ `ui_clone/gates/hover_probe.py` → `hover-fallback.json`), which gives every hoverable entry (transition-spec hover entries plus `bundle-extraction.json` `hoverSizeExpansions` — JS-driven size expansions such as nav pill labels, now extracted deterministically by `scripts/extract/_bundle_extraction.py`) a verdict: event-driven delta (`verified`), covering impl `:hover` CSS rules incl. nested/@media (`static-verified`), or `fail`. For the size channel a `:hover{width:auto}` rule can be neutralized by a higher-priority `width:0 !important` base, so rule presence is not proof: the probe drives a REAL (CDP `agent-browser hover`) hover and records the computed end-state (`forcedHover`), and a mounted size entry that does not expand under forced hover fails rather than static-verifying. The probe resolves the rendered-VISIBLE target via the shared `visible-identity` primitive and matches each `:hover` rule by whether its base selector applies to that target (not a substring of the token), so a `display:none` superstring-class decoy cannot satisfy the entry. Provenance: a self-attested env flag is not enough — the probe writes a scan receipt (`.hover-scan-receipt.json`) INSIDE the impl tree only when a live scan ran, and `runtimeScanned` is true only when the env flag AND that receipt file both exist; the post-implement consumer binds the receipt to `impl_root` + mtime via the path-check machinery (like junk-token's `implSrcDir`), so a pass computed from fabricated/replayed samples, a forged measured-file, an env-flag spoof with no receipt, or a `runtimeScanned=true` artifact with no resolvable impl tree is all rejected by both the verdict and `verification_plan.py`. Scrub entries whose spec declares per-element evolution (per-card y/x/rotate/z-index at progress fractions) are judged by per-child mechanics inside `transition-fires` — binary "varied" is not sufficient: each declared channel must move across the sampled fractions and the children must move relative to each other (Lenis-style unscrollable pages stay honest-unmeasurable). Specs with `dynamic:true` timer/carousel entries get `masked-region-motion.json` (`skills/visual-debug/scripts/masked-region-motion-proof-check.sh` + `ui_clone/gates/masked_region_motion.py` — live DOM sampling at ~250ms for ≥1.5× the declared interval, retrying to ~2.2×; verdicts: ≥2 distinct states, change cadence within declared interval ± max(450ms, 15%), changed-channel set covering the spec-declared channels, and bundle item-sequence membership; insufficient spec params are an explicit unmeasurable failure). Specs with `dynamic:true` masked selectors also get `masked-region-static.json` (`skills/visual-debug/scripts/masked-region-static-check.sh` + `ui_clone/gates/masked_region_static.py` — the dynamic mask absorbs MOTION only, and `visibility:hidden` also hid the region's STATIC style/geometry from section-compare, video-motion, and the motion proof, so a static defect under a mask passed every gate (loop-11 eatReal "Eat Real" h2 lost `text-align:center`). This check probes the live impl DOM un-masked and compares phase-free computed styles (default: text-align, justify-content, align-items, font-family, font-weight, color — viewport-independent; `UI_CLONE_MRS_PROPS` tunes the list) against the extraction-time ref ground truth in `dom-scaffold.json`; justify-content/align-items are only compared on flex/grid containers, and attribute/pseudo selectors the scaffold cannot resolve are reported unmeasured, never compared. The probe resolves the **rendered-visible** match via the shared `visible-identity` primitive (`skills/visual-debug/scripts/lib/visible-identity.js` + `ui_clone/gates/visible_identity.py`). That primitive is pixel-truth, not property-enumeration: the collector emits `Element.checkVisibility({checkOpacity,checkVisibilityCSS,contentVisibilityAuto})`, fully-clipping `clip-path`/`clip` and `filter:opacity(0)` flags, an ancestor overflow-clip flag, an `elementsFromPoint` hit-test at the rect centre (null for off-viewport / `pointer-events:none` so legit content is not false-failed), and the resolved text colour + effective cascaded background; `paints_text` requires a contrast ratio above a floor (white-on-white reads invisible), an alpha above `0.1`, and a font strictly above the floor, while `::before`/`::after` and replaced content count as paint. The probe runs at every fan-out viewport (text-align is viewport-dependent via @media, so a single-viewport probe is blind) and the verdict buckets impl records per viewport, failing a mismatch in ANY. The gate pairs ref↔impl by that rendered-visible result, not by DOM index, so a decoy matching the masked selector — `display:none` ahead of the real element, or an off-screen clone while the real heading is renamed — can no longer absorb the comparison (more visible matches than the ref expects is an ambiguous fail), and it samples until MutationObserver/rAF quiescence (`UI_CLONE_SETTLE_FRAMES` stable frames) past a wall-clock floor (`UI_CLONE_SETTLE_FLOOR_MS`, clamped ≥8000ms — exceeding plausible deferred-defect timers), recording EVERY frame as `stylesSamples`, so a defect that flips in after a fixed window (a 7000ms late flip) is measured at its settled STATE and a series that never stabilises fails as still-changing (`settled_state` in the shared primitive). The complementary geometry half is closed in `enumerate-sections.js`: mask-hidden elements (whose `visibility:hidden` preserves layout) are no longer dropped from `contentBox`/`contentGroups`, so `alignment-parity` measures the masked footer cards' off-center geometry it previously excluded). Bundles that declare an active-state width reveal also get `state-reveal.json` (`skills/visual-debug/scripts/state-reveal-proof-check.sh` + `ui_clone/gates/state_reveal.py` — the hover-fallback gate only covers HOVER-triggered reveals, so an active-state (scroll) reveal had no verification (loop-11: scrolling swapped the nav pill's active state but the newly-active button's label stayed `width:0`). The bundle reveal `initial:{width:0} -> animate:{width:<active flag>?"auto":0}` is captured as `bundle-extraction.json` `activeStateExpansions` (`scripts/extract/_bundle_extraction.py` `_extract_active_state_expansions`, the active-state analogue of the `hoverSizeExpansions` extraction); the gate drives the state change by scrolling each section into active state and asserts the active button's label expands to show its text — `box >= UI_CLONE_STATE_REVEAL_RATIO (default 0.5) * scrollWidth` (site-independent: a collapsed label shows ~none of its text, a revealed one ~all). The reveal must also actually PAINT: the probe records the active label's computed `colorAlpha`/`opacity`/`font-size` and on-screen position, and a box that fills its content width while rendering no visible text (color:transparent, opacity:0, or font-size:0 — an empty pill) is a fail, not an unmeasurable warn; an off-screen decoy (left:-99999) carrying the active flag is excluded so it cannot mint a passing observation while the user-visible label stays collapsed. Ref truth is bundle/extraction only — no live ref browsing; honest-unmeasurable with remediation when no per-state reveal is declared or no active label is observed. Env thresholds are clamped to sane bands (`UI_CLONE_STATE_REVEAL_RATIO` to [0.4,0.95], `MIN_CONTENT_PX` to [4,40]; the falsy-0 fallback is fixed) and the EFFECTIVE clamped values are recorded in the artifact, so an attacker-tuned threshold cannot soften the gate below the loop-11 defect's real ratio; the alignment tolerance knobs are clamped the same way. The verdict stamps `runtimeScanned` only on the live state-sweep path, and the post-implement consumer rejects a state-reveal pass that has no live scan or whose effective threshold is out of band).
- `boundary` (after 8-pre-bound): `responsive/boundary-collisions.json` — must be `[]`. Produced by `skills/visual-debug/scripts/breakpoint-collision-check.sh` (REF_DIR env required to write the artifact). Catches Tailwind ↔ project @media inclusive-boundary collisions (Root Cause J in diagnosis.md). The script tracks three signals; only signal 2 (isolated overflow spike) and signal 3 (rootFontSize jitter) become gate-blocking findings. Signal 1 (matchMedia overlap at the boundary) is W3C-spec inevitable — reported on stdout as advisory only and never written to the JSON artifact.
- `font-parity` (after 8b-pre): `font-parity.json` — `parity:"match"` PASSes (with silent-fallback guard via `document.fonts.check()`); `parity:"mismatch"` requires `asset-substitution.json` with at least one `fonts[]` entry. Produced by `skills/visual-debug/scripts/font-parity-check.sh`.
- `section-compare` (Stop hook): `tmp/ref/<c>/sections/result.txt` — 0 ❌ FAIL lines and 0 "⚠️ MISSING impl" lines. `STRUCTURAL_ONLY` rows are allowed only as scoped substitution evidence: broad coverage warns at 30%+ and fails above 50%, because those rows skip pixel AE polishing.

## Verification strictness knobs

- `UI_CLONE_STRICT_WARNINGS=1` (or `"strictWarnings": true` in `verification-plan.json`) promotes selected fidelity advisory rows such as `tree-diff`, `scroll-coverage`, `keyframes-diff`, and `visual-fidelity-judge` from warning to blocking failure for release/closeout runs. The VLM judge remains `warn` by default because it assesses the complete rendered/motion result. `runtime-text-sequence` is different: visible UI copy and document order are blocking by default, including in rapid phase and for legacy plans that still declare `severity:"warn"`. Its bounded phase-variance path remains valid only when the runtime comparator proves recurrence on both sides; missing, stale, malformed, or mismatched evidence fails closed.
- `UI_CLONE_RESOURCE_MIRROR_REQUIRED=1` makes the Step 2.5b browser resource mirror a hard extraction requirement. Without it, `resource-manifest.json` remains recommended recovery evidence and mirror failures do not abort deterministic Phase 2.
- `UI_CLONE_LIVE_CURRENT_MODE=pin` is the default for `live-parity-sweep.sh`; it pauses common media/carousel/animation APIs before comparing. Use `snapshot` only when raw live behavior is intentionally under review.

**Frozen same-frame section-compare on the verify path (Task B / loop-16 capture variance).** A cold clone hit run-to-run AE variance on framer scroll-scrub sections — a faithful section PASSes one run and saturates the next — because the default single-pass `section-compare` captures the ref AND the impl LIVE each run, landing different scrub frames. At `UI_CLONE_VERIFY_TIER=comprehensive`, `run-required-checks.sh` dispatches `skills/visual-debug/scripts/section-compare-frozen.sh` instead of bare `section-compare.sh`: a three-pass orchestrator that (1) freezes the ref ONCE (`RECATCH_REF=1`, recording `sections/ref-scroll-positions.json`), (2) captures the REF a second time through the impl path at those frozen positions and snapshots the crops to `ref-calib/` (the ref's OWN same-frame scrub noise floor; `SECTION_SKIP_IMPL_RESIZE=1` preserves native box dims), then (3) captures the REAL impl at the SAME forced scroll frame (`RECATCH_REF=0` + frozen positions) so pixel AE is same-frame and meaningful. It is viewport-aware: a multi-viewport run fans out into `sections/viewports/<WxH>/sections/{ref,impl,ref-calib}/`, so each viewport gets its own per-viewport impl-path calib (closes the multi-viewport copy-calib gap) and `VIEWPORTS` multi-viewport enforcement is preserved. The frozen row carries its own `ROW_TIMEOUT_SEC` (default `600 × viewport-count`, overridable via `SECTION_FROZEN_TIMEOUT_SEC`) instead of the shared 180s single-check budget. Detection is NOT discarded for the variance fix: `section_dynamic.dynamic_section_verdict` adds a same-frame **AE ceiling** (`dynamic_ae_ceiling` = the ref's own `selfAePerMpx × mult + eps`) as a MUST-ALSO-PASS gate alongside the dssim floor — a wrong-content defect at the same frame exceeds the ceiling and FAILS even if dssim ≤ floor (closing the dssim-only defect-hiding hole the adversarial review flagged). If pass-2A produces no calib crops the wrapper writes `sections/ref-calib-missing.txt` and SKIPs (exit 2) rather than silently reverting to single-pass strict AE. `quick`/`standard` tiers keep the fast single-pass `section-compare` (with `VIEWPORTS`). Live-validated: single-viewport ref-vs-ref selfpass 16/0/2; multi-viewport (375×812 + 1280×800) 17/0 + 16/0 with per-viewport calib materialized.

Video-motion splash runs are determinism-hardened: frame extraction is wiped-before/fail-hard/stderr-surfaced with per-recording fingerprints (stale-frame reuse structurally impossible), splash recordings are navigation-anchored and duration-validated with up to 3 re-record attempts, tail-only/truncated captures are `UNMEASURABLE` hard errors (exit 2) instead of vacuous passes, a comparison with 0 measurement rows hard-errors, every complete `video-motion-result.txt` ends with a `# video-motion-compare: COMPLETE` sentinel, and `transition-proof-rollup.sh` rejects results missing it (dispatcher-truncation class). `UI_CLONE_VMC_JITTER_FRAMES` (default 1) lets a failing frame retry against ±N neighboring impl frames — phase-jitter compensation between two independent recordings, not threshold widening. The scroll-mode chunked resume manifest (`ui_clone/scroll_chunk_manifest.py`) binds a captured position not just by on-disk existence+size but by a per-frame content fingerprint recorded at capture and a run identity (orig/impl URL, viewport, action, dynamic-mask selectors, script version): a frame later overwritten with different bytes no longer counts as captured (re-captured on resume), and a prior green run's manifest+frames replayed for a different page/viewport/action is not resumable. Crucially the manifest is a CACHE HINT, never the verdict basis (batch-7 ITEM 6): before the SSIM verdict the gate independently re-derives, FROM DISK, the frame count (must equal the scroll positions) and per-frame fingerprints, and rejects partial-run padding (the same content across ≥3 distinct positions) — so duplicated frames can no longer mint an 11/11 pass; non-scrolling pages (no scroll range) are exempt from the distinctness check. Resume is additionally bound to a LIVE page-region digest captured at gate start (a value not reproducible without visiting the target page), so a manifest whose self-asserted identity matches but whose frames were recorded under a different page fails the digest check and forces a re-capture. **batch-8 minor:** the duplicate-frame padding check no longer false-fails a legitimately-static sticky/pinned region — the capture loop records each frame's ACHIEVED `window.scrollY` under `scrollPositions`, and `verify_side` fails a run of identical frames only when their recorded offsets are DISTINCT (a real sweep that moved); identical frames at the SAME offset are a static region, not padding. When `scrollPositions` is absent (older manifests) the legacy index-distinctness fallback applies, so the padding cheat still fails.

**Round-3 hardening (batch-8) of the pixel-truth visible-identity primitive and the anti-cheat gates** (`skills/visual-debug/scripts/lib/visible-identity.js` + `ui_clone/gates/visible_identity.py`, mirrored byte-for-byte): the `elementsFromPoint` hit-test now decides off the TOPMOST painted node ONLY — accept when the topmost hit is the element, its own descendant, or a transparent ancestor; any unrelated opaque node on top (a z-index cover or an opaque canvas painted over the text) reads `blocked` ⇒ not visible. Being merely *present* in the paint stack is no longer enough (batch-8 ITEM 1). Two more imperceptible-but-laid-out hides are caught by explicit flags: `content-visibility:hidden` with a `contain-intrinsic-size` box (checkVisibility reports only `:auto`, not `:hidden`) and a large off-box `text-indent` under an overflow clip that shoves the glyphs out of the painted rect (batch-8 ITEM 2/3). The contrast skip over a background-image now requires positive PAINT evidence — a `url(...)` image decoded larger than a 1×1 placeholder, or a cover/contain layer when the intrinsic size is not yet decodable — so invisible white-on-white text under a 1×1/transparent/empty image or a same-colour gradient is still caught (a gradient's averaged stop colour is folded into the contrast backdrop); an honest hero photo overlay still passes (batch-8 ITEM 5). The settle loop's resolve-without-quiescence point is now jittered into a randomized `[floor, maxMs]` band (maxMs raised to floor+8000, kept only as a runaway bound) so a defect deferred just past the old fixed `floor+4000` cap can no longer be timed to escape, and the masked-region probe drives a representative scroll sweep + scroll-into-view before sampling so scroll-/once-triggered defects materialize and a below-fold heading is not measured off-screen (batch-8 ITEM 4). The junk-token scan adds a CSS-file declaration value-walk (`content:"undefined"`, `fill:undefined`) and `setAttribute`/`dataset`/`style.cssText` JS-sink regexes to the authoritative STATIC block, plus a best-effort computed-`::before`/`::after`/`fill`/`stroke` read and a bounded click/hover/hashchange interaction sweep at runtime (batch-8 ITEM 6). Two honest false-positives the per-viewport/on-screen machinery produced are fixed: a masked selector legitimately `display:none` at a narrow `@media` breakpoint (but visible at another probed viewport) is recorded responsive-hidden, not absent, and a faithful below-fold masked element is measured (below-fold tolerated; the x-axis + above-viewport off-screen-decoy gates stay strict) — a selector visible NOWHERE still fails (batch-8 ITEM 9/10). The state-reveal env-threshold band-check is now fail-CLOSED: a `pass` must record both effective thresholds as real numbers in band — an artifact that omits them or stringifies them (`"0.01"`) is rejected, closing the A5 env-tuning forge — and `masked-region-static`/`state-reveal`/`alignment-parity`/`junk-token` join `STRICT_ALWAYS` (no rapid-phase downgrade) while `hover-fallback` joins `STATUS_REQUIRED` (a status-less artifact no longer vacuously passes) (batch-8 ITEM 8).

**Round-4 hardening (batch-9)** closes the residual bypasses + the topology-hit-test false-positive the R4 adversarial panel found on top of batch-8. (ITEM 1) The occlusion hit-test is now **multi-point and paint-aware**: it samples a 5×3 grid across the element's content rect (clipped to viewport) and counts a point occluded ONLY when the topmost FOREIGN node there paints materially OPAQUE pixels — effective `opacity × background-color` alpha ≥ `OPAQUE_ALPHA` (0.5), a replaced element, or a covering `url(...)` image. The element reads `blocked` only when ≥ `MATERIAL_OCCLUSION` (0.5) of measured points are opaquely occluded. This catches a 95%-covered heading with a clear-centre strip (the single-centre probe read `self`) AND stops false-positiving on a fully transparent click-catcher overlay or a 4% translucent sticky-nav scrim (the topmost node at the centre but readable through). The verdict stays a `self`/`blocked`/null string consumed by `is_rendered`; the shared `occludedVerdict` tally + `OPAQUE_ALPHA`/`MATERIAL_OCCLUSION` constants are mirrored on the python half. (ITEM 2) `masked-region-static` per-viewport expected visibility is now derived from the **REF**, never the impl's own `sel_visible_anywhere`: a 0-rendered-visible impl bucket is excused (responsive-hidden) ONLY at a viewport the ref itself hides (`ref_hidden_viewports`, fed by the optional `ref-viewport-visibility.json` ref-fanout artifact); absent that evidence the gate is **fail-closed** (the single-viewport ref shows the element, so it is expected at every probed viewport), so an impl that `@media display:none`-hides a heading the ref renders at mobile is an absent defect, not a responsive exemption. ## Rejected design notes

**Rejected: fingerprint-cached check reuse.** A proposal to skip re-running a check when its input fingerprint (impl source-tree hash + relevant ref-artifact hashes + check-script hash) exactly matches the fingerprint recorded in the last GREEN artifact was reviewed and **declined** (design review 2026-06-12). The intended saving is only 1–3 min/loop, against an unbounded anti-cheat risk: (1) no per-check input-set contract exists — `verification-plan.json` rows carry no file-input lists and the dispatcher maps args, not inputs, so mapping drift would cause silent stale-GREEN reuse; (2) the "deterministic" candidates are not pure file-IO (junk-token has a live-DOM mode; alignment depends on `UI_CLONE_ALIGN_*` / `UI_CLONE_GENERATED_EVIDENCE_DIRS` env state); (3) consumer-side fingerprint recomputation is intractable today (the canonical verify stamp only hash-pins `sections/`+`result.txt`), and cached old-mtime artifacts break the dispatcher/gate/Stop-hook freshness checks in both directions. The tier system already addresses cost where it matters, and `section-compare` has its own scoped content-hash fast path. No caching is implemented; checks always re-run.

## Ref-vs-ref self-pass invariant (batch-11)

A gate must PASS when run against its own reference (ref-as-impl). This is a THIRD verification axis beyond bypass-resistance ("a cheat must FAIL") and false-positive-resistance ("an honest impl must PASS"): it catches **achievability** bugs — a frozen, adversarially-hardened gate that a CORRECT impl cannot satisfy because the gate consumes an artifact no pipeline step produces, or derives an input from the wrong layer. Six adversarial rounds (batch-5..10) checked the first two axes but never this one (their panels fed gate inputs directly instead of producing them through the pipeline), so the ITEM 1-4 class survived to loop-e2e-12.

- CI enforcement: `tests/gates/test_ref_self_pass.py` — for each gate, the ref-as-impl achievability scenario must PASS, paired with a real-defect NEGATIVE so the self-pass relaxation never blunts detection.
- Full-pipeline proof: `scripts/ci/ref-vs-ref-selfpass.sh` (opt-in, `UI_CLONE_REF_SELFPASS=1`; the frozen ref corpus is gitignored so it never runs on CI) drives each block-severity check SCRIPT with the live reference URL as the impl URL. **batch-12 ITEM 6:** it now runs EVERY block-severity LIVE-PROBE gate (led by section-compare; full list in the script header), pins out-dirs to the ref dir, orders dependencies (section-compare before alignment-parity/-sweep), and treats a REQUIRED gate that produces NO artifact as a FAILURE (the old exit only checked `fail`, so a gate that produced nothing silently SKIPped); a setup error (exit 2) stays a SKIP. STATIC-SOURCE gates (file-IO over an impl source tree) are out of scope for live-ref-as-impl (no "reference source tree") and stay enforced at the verdict layer. Run a subset with `UI_CLONE_SELFPASS_ONLY="<gate> <gate>"`. NOTE the LIVE-vs-FROZEN gates (a fresh live probe vs the captured dom-scaffold/plan) only self-pass against a FRESH corpus — a stale/inherited corpus surfaces real live-render drift (cardinality/style), which is closed by re-capturing the corpus, never by loosening the gate.

When adding or hardening a gate, add a ref-vs-ref self-pass assertion alongside the bypass and false-positive ones.
